# GxEPD2 Examples — Seeed Studio reTerminal E1002

Arduino sketches for the **reTerminal E1002** e-paper display subsystem:

- **Display:** 7.3″ 6-color ACeP e-paper, 800 × 480 px
- **Panel:** GDEP073E01 (ED2208 controller)
- **Colors:** Black, White, Red, Green, Blue, Yellow — **no orange**
- **MCU:** XIAO ESP32-S3 (on the E1002 carrier board)

---

## 🚨 Required Arduino IDE Settings (All Sketches)

> **The board will not flash or run correctly without these two settings.**
> Apply them before compiling any sketch in this folder.

| Setting | Path in Arduino IDE | Required Value |
|---|---|---|
| **PSRAM** | Tools → PSRAM | **OPI PSRAM** |
| **Upload Speed** | Tools → Upload Speed | **115200** |

The default Arduino IDE upload speed is too high for this board and causes
flashing failures.  OPI PSRAM must be enabled even for sketches that do not
explicitly use PSRAM — without it the ESP32-S3 PSRAM is inaccessible and the
board may behave erratically.

## ⚠️ Library Note — Different from Seeed Documentation

> The [official Seeed wiki](https://wiki.seeedstudio.com/reterminal_e10xx_with_arduino/) instructs you to install
> **[Seeed_GxEPD2](https://github.com/Seeed-Projects/Seeed_GxEPD2/)** — a Seeed fork of GxEPD2.
>
> **These examples use the original upstream library instead:**
> ### [ZinggJM/GxEPD2](https://github.com/ZinggJM/GxEPD2)
>
> Install it via **Arduino Library Manager → search "GxEPD2" → by Jean-Marc Zingg**.
> Do **not** install `Seeed_GxEPD2` alongside it — the two libraries conflict.

The upstream library has full support for the GDEP073E01 panel (`GxEPD2_730c_GDEP073E01`)
and receives regular upstream updates, which is why we prefer it here.

## Examples

### `Demo/` — Comprehensive drawing demo

Exercises all GxEPD2 drawing primitives on the 6-color panel without any external
storage. Good as a first smoke-test after wiring up the hardware.

**Features:**
- Filled rectangles, circles, and triangles in all 6 colors
- Text rendering with multiple GFX fonts and sizes
- Color palette swatch
- Gradient-style blocks

---

### `Demo_Image/` — Flash-embedded image

Displays a pre-converted image that is compiled directly into the firmware
(stored in program flash). No SD card or external storage needed.

The image header (`mocha800x480.h`) is generated by `convert_image.py` and
contains the pixel data as a nibble-packed C array:
- 2 pixels per byte, MSB nibble = left pixel
- Color codes: `0`=Black `1`=White `2`=Green `3`=Blue `4`=Red `5`=Yellow
- 800 × 480 pixels → 192 000 bytes in flash

**Workflow:**
```bash
# Convert any image to a C header (quantized to 6 e-ink colors)
python3 convert_image.py yourphoto.jpg mocha800x480.h
# Then recompile and upload the sketch
```

---

### `Demo_SDcard/` — Raw binary image from SD card

Loads a pre-converted raw binary image from an SD card and displays it.
The binary format (nibble-packed, 192 kB) is generated by `convert_image.py`
and is the most compact on-card representation — no parsing overhead at runtime.

The full 192 kB image is buffered in **PSRAM** before rendering.

**Workflow:**
```bash
# Produce a .bin file for the SD card
python3 convert_image.py yourphoto.jpg /Volumes/SD/images/photo.bin
```

Then set `IMAGE_PATH` at the top of the sketch and upload once.
Swap images by replacing the `.bin` file on the card — no reflashing needed.

---

### `Demo_BMP/` — Standard BMP image from SD card

Loads a standard 24-bit or 32-bit uncompressed Windows BMP from an SD card.
Unlike `Demo_SDcard`, the file is a universally readable format — any image
viewer or OS can open it, making it easy to prepare images without a custom tool.

**How it works:**
1. BMP header is parsed to extract dimensions and pixel data offset
2. Each row is read from the SD card (480 seeks, once — not repeated)
3. Pixels are color-quantized to the 6 e-ink colors on the ESP32 using
   nearest-neighbor Euclidean distance in RGB space
4. The result is packed into a **192 kB nibble buffer in PSRAM**
5. `drawNative()` renders the buffer in a single fast panel write

This avoids the multi-minute penalty of calling `drawPixel()` inside GxEPD2's
page loop (which would repeat all 480 SD seeks × 12 pages = 5 760 seeks and
call `drawPixel()` 4.6 million times).

**Workflow:**
```bash
# Resize + quantize preview; produces image.bmp and image_preview.png
python3 convert_image.py yourphoto.jpg /Volumes/SD/images/photo.bmp --save-preview

# Or with uv (no pip install needed):
uv run --with Pillow --with numpy python3 convert_image.py yourphoto.jpg /Volumes/SD/images/photo.bmp
```

Then set `BMP_PATH` at the top of the sketch and upload once.

|---|---|---|
| EPD SCK | 7 | shared with SD |
| EPD MOSI | 9 | shared with SD |
| EPD CS | 10 | |
| EPD DC | 11 | |
| EPD RST | 12 | |
| EPD BUSY | 13 | |
| SD SCK | 7 | shared with EPD |
| SD MISO | 8 | SD only |
| SD MOSI | 9 | shared with EPD |
| SD CS | 14 | SD examples only |
| SD EN | 16 | power enable, active-high; SD examples only |
| SD DET | 15 | card-detect, active-low; SD examples only |
| UART1 TX | 43 | carrier board USB-UART bridge |
| UART1 RX | 44 | carrier board USB-UART bridge |

## Serial Logging

All sketches log to **both** serial ports simultaneously:

- `Serial1` (UART1) on GPIO 43/44 — always available via the E1002 carrier
  board's USB-to-UART bridge, regardless of USB CDC settings
- `Serial` (USB CDC) — available when **USB CDC On Boot** is enabled in the
  Tools menu

Connect at **115200 baud**.
